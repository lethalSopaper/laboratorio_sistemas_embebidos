\section*{\centering \fontsize{14}{17}\sffamily\selectfont Conversión Analógica-Digital, PWM e Interfaz Gráfica}

\section*{\centering \fontsize{14}{17}\sffamily\selectfont Objetivo}

Desarrollar un sistema embebido utilizando la tarjeta ESP32-S3 que integre la lectura de un potenciómetro a través del convertidor analógico-digital (ADC) para controlar el brillo de un LED mediante una señal PWM y un transistor MOSFET, visualizando simultáneamente los datos obtenidos en valor absoluto, porcentaje y representación gráfica en una pantalla OLED vía I2C; aplicando además buenas prácticas de programación al estructurar el código fuente en archivos separados (encabezados e implementación) para mejorar la modularidad del proyecto.

\subsection*{\fontsize{12}{17}\sffamily\selectfont Ejercicio 2}

Para el segundo ejercicio, se desarrolló el código encargado de adquirir los datos del convertidor analógico-digital (ADC) y generar la señal PWM correspondiente para el control de iluminación del LED. Adicionalmente, se implementó la interfaz gráfica en la pantalla OLED utilizando la librería u8g2. En la siguiente imagen se muestra el funcionamiento del programa, donde se aprecia el despliegue de los tres elementos requeridos, el valor directo del ADC en un rango de 0 a 4095, su equivalencia porcentual (de 0 a 100\%) y la representación gráfica dinámica que ilustra la lectura actual del potenciómetro. Lo más relevante dentro del código:

\begin{lstlisting}[style=cstyle, caption={Ciclo principal del programa.}, label={lst:main}]
    void app_main(void)
{
    pantalla_iniciar();
    adc_iniciar();
    pwm_iniciar();

    while (1)
    {
        int lectura = adc_leer();

        pwm_actualizar(lectura);
        pantalla_mostrar(lectura);

        vTaskDelay(pdMS_TO_TICKS(PERIODO_MS));
    }
}
\end{lstlisting}

\begin{lstlisting}[style=cstyle, caption={Función para mostrar los datos en la pantalla OLED.}, label={lst:mostrar}]
    int porcentaje = (lectura * 100) / ADC_MAX;
    // ... (Configuración de texto)
    snprintf(texto, sizeof(texto), "ADC: %04d | %3d%%", lectura, porcentaje);

    // Dibujo de la barra de progreso
    u8g2_DrawFrame(&u8g2, BARRA_X, BARRA_Y, BARRA_ANCHO, BARRA_ALTO);
    if (porcentaje > 0) {
        u8g2_DrawBox(&u8g2, BARRA_X, BARRA_Y, porcentaje, BARRA_ALTO);
    }
\end{lstlisting}

\subsection*{\fontsize{12}{17}\sffamily\selectfont Ejercicio 3}

Dado que el comportamiento visual y funcional del sistema se mantiene exactamente igual que en el Ejercicio 2, el enfoque de este apartado se centra exclusivamente en la reestructuración del código. A diferencia de la implementación anterior, el proyecto se dividió en tres archivos clave para mejorar su modularidad: un archivo de encabezado (\texttt{perifericos.h}) para las declaraciones y macros, un archivo de implementación (\texttt{perifericos.c}) con el cuerpo de las funciones, y el archivo principal (\texttt{main.c}) enfocado únicamente en la ejecución de la función principal. De lo más relevante dentro del código tenemos \texttt{perifericos.h}, que destaca el uso de \texttt{\#pragma once} para evitar inclusiones múltiples y el uso de \texttt{extern} para compartir los handlers sin redefinirlos.

\begin{lstlisting}[style=cstyle, caption={Archivo de encabezado \texttt{perifericos.h}.}, label={lst:perifericos_h}]
#pragma once

#include "u8g2.h"
#include "esp_adc/adc_oneshot.h"

// ... (Definición de constantes y macros)

// Declaracion de handlers (extern)
extern u8g2_t u8g2;
extern adc_oneshot_unit_handle_t adc;

// Prototipos de funciones
void pantalla_iniciar(void);
void pantalla_mostrar(int lectura);
// ...
\end{lstlisting}

Y el archivo principal \texttt{main.c} que se centra en la función principal del programa, manteniendo la lógica de adquisición de datos y actualización de la pantalla.

\begin{lstlisting}[style=cstyle, caption={Archivo principal \texttt{main.c}.}, label={lst:main_c}]
#include "perifericos.h"
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"

void app_main(void)
{
    // La lógica de inicialización y el ciclo infinito
    // se mantienen idénticos, pero el código ahora
    // reside en perifericos.c
// ...
\end{lstlisting}

Con esto obtenemos el mismo resultado visual y funcional que en el Ejercicio 2, pero con un código más organizado y modular, facilitando su mantenimiento y escalabilidad.

\section*{\centering \fontsize{14}{17}\sffamily\selectfont Análisis}

Las variables \texttt{ADC\_BITWIDTH\_12} y \texttt{ADC\_ATTEN\_DB\_12} son fundamentales para establecer una resolución de 12 bits, otorgando un rango de valores de 0 a 4095, y aplicar una atenuación que permite medir voltajes de hasta \(\approx\)3.3V en la tarjeta de desarrollo. Alterar esto afectaría directamente la medición, por ejemplo, reducir la atenuación a 0 dB saturaría la lectura con voltajes cercanos a 1.1V, mientras que disminuir el ancho de bits restaría precisión y granularidad a los datos obtenidos. Durante las lecturas, es común observar ruido en los valores, un fenómeno que afecta a todos los microcontroladores debido al ruido eléctrico interno y a las interferencias electromagnéticas captadas por el cableado del circuito.

Por otro lado, la temporización y las frecuencias de actualización juegan un papel crítico en el control de actuadores y la visualización gráfica. Modificar considerablemente la frecuencia de la señal PWM generaría problemas perceptibles:

\begin{itemize}
    \item Si la frecuencia es demasiado baja, el LED podría parpadear visiblemente, afectando la experiencia del usuario.
    \item Si la frecuencia es excesivamente alta, la capacitancia parásita del MOSFET podría impedir una conmutación limpia, provocando distorsión en la señal o sobrecalentamiento del componente.
\end{itemize}

En cuanto a la interfaz gráfica, la velocidad de actualización de la pantalla podría optimizarse a nivel de hardware aumentando la frecuencia del reloj del bus I2C; y, a nivel de software, refrescando únicamente los elementos dinámicos, como la barra de progreso, en lugar de limpiar y reescribir todo el buffer del display en cada iteración.

\section*{\centering \fontsize{14}{17}\sffamily\selectfont Conclusiones}

El desarrollo demuestra la versatilidad del sistema construido, ya que la arquitectura base puede extrapolarse a diversas aplicaciones prácticas. El potenciómetro, utilizado como entrada analógica, puede ser sustituido por sensores como fotorresistores (LDR) para medir intensidad luminosa o joysticks para controles direccionales. De igual forma, el LED puede reemplazarse por otros actuadores de corriente continua, como motores pequeños, ventiladores o zumbadores, aprovechando el transistor MOSFET para manejar mayores exigencias de corriente. Para garantizar un funcionamiento óptimo en cualquier escenario, es indispensable mitigar el ruido en el ADC implementando soluciones de hardware, como agregar capacitores de desacoplo para filtrar la señal, y soluciones de software, mediante el cálculo de promedios móviles que estabilicen las lecturas.

Finalmente, desde la perspectiva del desarrollo de software, el proyecto resalta la importancia de estructurar el código fuente de manera adecuada. Separar el programa utilizando un archivo de encabezado (\texttt{perifericos.h}) para las macros y declaraciones, junto con un archivo de implementación (\texttt{perifericos.c}) para la lógica de los controladores, otorga ventajas significativas frente a concentrar todo en el \texttt{main.c}. Esta modularización facilita la lectura y el mantenimiento del proyecto al ocultar los detalles de bajo nivel, además de permitir la reutilización de los componentes programados en futuros desarrollos de manera eficiente.
